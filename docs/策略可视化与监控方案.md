# 策略可视化与监控方案（需求评审）

> 日期：2026-09-07　|　触发：James 提出三个可视化需求，要求按标准量化研究者视角评审
> 结论先行：**三个需求全部合理，且正好构成"预测 → 决策 → 执行"完整监控链**；底座大半已存在，缺的是可视化层和分域诊断

---

## 一、需求评审（业界对标）

| # | 你的原话 | 业界标准名称 | 合理性 |
|---|---|---|---|
| 1 | 每版策略预估的 α 在不同股票、不同周期上的准确性可视化 | **Signal Quality Monitoring**（信号质量监控/IC 看板） | ✓ 机构标配。分股票（按市值/波动/行业分桶）、分周期（分年度/滚动窗口）诊断预测在哪些子域失效，是 IC 异动诊断的标准做法 |
| 2 | 策略在不同标的上选出的持仓决策结果 | **Holdings Report / Decision Snapshot**（持仓穿透/决策快照） | ✓ 复盘与合规标配。回答"为什么是这 30 只而不是别的" |
| 3 | 完整决策结果：买卖记录、资金曲线等历史周期信息 | **Trade Blotter + Equity Curve**（交易流水+净值曲线） | ✓ 最标准的回测报告形态 |

三个需求的内在关系——你凭直觉摸出了机构研究的完整链路：

```
需求1 预测层监控          需求2 决策层透明            需求3 执行/结果层记录
"预估得准不准"     →      "选了什么、为什么选"   →    "买了什么、赚了多少"
(IC/分桶/版本对比)        (打分分布/入选理由)          (交易明细/净值/成本)
```

## 三、三个脚本规格

### 脚本 1：`scripts/alpha_monitor.py`（需求 1）

**输入**：一个或多个 strategy_id（版本对比就靠它，如 `prod_6f_eq` vs `prod_6f_win92`）；时间范围
**数据源**：factor_value 合成分重算 + daily_quote 前向收益（复用 alpha_accuracy 的对齐逻辑）
**输出**：HTML 单页，图表清单：

| 图 | 内容 | 回答的问题 |
|---|---|---|
| IC 时序 | 每期 IC 柱状 + 12 期滚动均线 + 累计 IC 线 | 信号什么时候强什么时候弱 |
| 分年度热力表 | 年×月 IC 热力图 | 衰减是从哪年开始的 |
| 分桶 IC | 按市值五分位/波动五分位/行业分组的 IC 对比柱状 | **预测在哪类股票上失效**（如小盘强大盘弱） |
| 版本对比 | 多 strategy_id 的滚动 IC/累计 IC 叠加 | 新版本是否真的更准 |
| 分位兑现曲线 | 十分位实际收益 vs 预测分（含 D10 倒挂标注） | 选股区是否健康 |

### 脚本 2：`scripts/decision_snapshot.py`（需求 2）

**输入**：--date 调仓日（默认最近一期）
**数据源**：signal_log + 当期 factor 截面重算
**输出**：HTML 单页：

| 图 | 内容 |
|---|---|
| 打分分布全景 | 全市场合成分直方图，标注 TopN / 分位窗口 / 入选边界 |
| 因子贡献热力图 | 入选 30 只 × 6 因子的 z 分矩阵（红绿），一眼看出"这只股是靠反转入选还是靠低波入选" |
| 边界对比表 | 入选末位 vs 落选首位：分数差多少、差在哪个因子 |
| 持仓迁移图 | 本期 vs 上期持仓的流入/流出/保留桑基图或对照表 |

### 脚本 3：`scripts/backtest_report.py`（需求 3）

**输入**：strategy_id + 起止日期
**数据源**：portfolio_nav + trade_log + index_daily（基准）
**输出**：HTML 单页：

| 图 | 内容 |
|---|---|
| 净值曲线 | 组合 vs 沪深300 vs 中证1000（**买卖点直接标在曲线上**，调仓日竖线） |
| 回撤水下图 | drawdown 序列，标注最大回撤区间 |
| 分年度绩效表 | 年化/夏普/回撤/超额/换手/成本拖累 |
| 换手与成本 | 每期换手率、双边成本时间序列 |
| 交易明细表 | 全部 BUY/SELL：日期、代码、价格、数量、盈亏（区间内已平仓的算单笔盈亏） |

## 五、技术选型

- **承载形式：HTML + ECharts 单页报告**（不是 matplotlib PNG、不是 alphalens）
  - 理由：① 项目已有 `echarts_report.py` 先例和 outputs/ 目录惯例 ② 交互（缩放/悬浮/图例开关）对"看曲线找问题"至关重要 ③ 一页多图可分享
  - matplotlib 仅留作 alphalens tear sheet 的存量用途
- **版本概念**：strategy_config 的 strategy_id 即版本（prod_6f_eq = v1，选股区修复后建 prod_6f_win92 = v2，LightGBM 后 = v3），同图叠加即可对比，不引入新机制
- **约定**：脚本统一输出 `outputs/<脚本名>_<strategy>_<日期>.html`，报告可重跑（数据全在 PG，无状态）

## 六、建议开工顺序

1. **脚本 3 backtest_report.py**（先看结果——净值+买卖点+交易明细是其他一切分析的锚）
2. **脚本 1 alpha_monitor.py**（再问为什么——预测质量诊断，直接服务 P0 选股区修复的验证）
3. **脚本 2 decision_snapshot.py**（后看过程——单期决策穿透）
4. 归因/基准监控视前三步使用频率决定是否升级为独立脚本（基准对照建议直接并入脚本 3）
